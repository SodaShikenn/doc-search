# コードレビュー観点

レビュー時に確認する観点のチェックリスト。指摘には must / want の温度感を付ける。

## 正しさ

- 仕様（チケット・設計ドキュメント）と実装が一致しているか
- 境界値（0件、1件、上限、月末・期末日付、うるう年）の考慮があるか
- 金額計算は整数（最小通貨単位）で行い、浮動小数点を使っていないか
- 端数処理（切り捨て・切り上げ・四捨五入）が税法・仕様の規定と一致しているか

## テスト

- 正常系だけでなく異常系（バリデーションエラー、権限なし、外部API失敗）のテストがあるか
- テストが実装の写経になっておらず、仕様を検証しているか
- 時刻依存のテストが固定時刻（time freeze）を使っているか

## 後方互換性

- APIレスポンスからフィールドを削除・リネームしていないか（クライアントが壊れる）
- DBマイグレーションが後方互換か（旧コードが動いている間に新スキーマが共存できるか）
- enum への値追加時、古いクライアントが未知の値を安全に無視できるか

## 可読性・設計

- 命名がドメイン用語（用語集参照）と一致しているか
- 早期リターンでネストが浅く保たれているか
- 「なぜ」がコードから読めない場合にコメントで補足されているか

## リリース安全性

- フィーチャーフラグの後ろに隠せる変更か
- ロールバック可能か（マイグレーションの down、データ埋め戻し）
- 障害時の影響範囲（全テナント / 一部テナント）を説明できるか
