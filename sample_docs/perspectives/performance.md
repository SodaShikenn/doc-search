# パフォーマンス観点

会計SaaSはテナントごとのデータ量の偏りが激しい（仕訳数万件〜数百万件）。「手元では速い」は当てにならない。

## データベース

- N+1 クエリになっていないか（ORMの遅延ロードに注意、preload / includes を使う）
- 実行計画を確認したか（EXPLAIN）。インデックスが効いているか、フルスキャンになっていないか
- 複合インデックスの列順は選択性の高い順・等値条件が先になっているか
- 大量データのテナントを想定した負荷テストをしたか（上位1%テナントのデータ量で試す）

## ページネーション

- OFFSET ページネーションは深いページで遅くなる。カーソル（keyset）方式を検討する
- 件数カウント（COUNT(*)）が重い場合は概算値や「もっと見る」方式にする

## 非同期化

- 重い処理（帳票生成、一括インポート、集計）は同期リクエストで行わずジョブキューに逃がす
- ジョブは冪等に作る（リトライで二重実行されても壊れない）
- 進捗をユーザーに見せる（ポーリング or WebSocket）

## キャッシュ

- キャッシュキーにテナントIDと対象期間を含める
- 無効化戦略を先に決める（更新時パージ / TTL / バージョンキー）
- キャッシュミス時のスタンピード対策（ロック、確率的早期更新）

## 計測

- 推測するな、計測せよ。APM（トレース）で遅いスパンを特定してから直す
- p50 ではなく p95 / p99 を見る。平均は外れ値を隠す
- スロークエリログとダッシュボードをリリース前後で比較する
