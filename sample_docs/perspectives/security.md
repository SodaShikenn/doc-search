# セキュリティ観点

設計レビュー・コードレビューで確認するセキュリティの観点。

## 認証・認可

- 認証（誰であるか）と認可（何ができるか）を混同していないか
- すべてのエンドポイントで認可チェックが行われているか（IDOR: 他人のリソースIDを直接指定してアクセスできないか）
- 権限チェックはコントローラ層ではなくドメイン層・クエリ層でも担保されているか

## テナント分離

- クエリに必ずテナントIDの絞り込みが入っているか（default scope / RLS の利用を推奨）
- JOINやサブクエリで別テナントのデータが混入する経路がないか
- キャッシュキーにテナントIDが含まれているか（キャッシュ経由の情報漏えい防止）

## 個人情報・機密データ

- 個人情報（PII）・マイナンバー・口座情報をログに出力していないか
- 不要になったデータの保持期間・削除ポリシーが定義されているか
- 暗号化: 通信はTLS、保存時はディスク暗号化＋アプリケーションレベル暗号化の要否を判断

## 入力値の扱い

- SQLはプレースホルダを使っているか（文字列連結でクエリを組み立てていないか）
- HTMLエスケープ漏れ（XSS）、特にユーザー入力をメール・PDF・CSVに埋め込む箇所
- CSVエクスポート時のフォーミュラインジェクション対策（先頭の = + - @ のエスケープ）
- ファイルアップロードの拡張子・Content-Type・サイズ検証

## 監査・追跡

- 重要操作（権限変更、データエクスポート、マスタ変更）に監査ログが残るか
- 監査ログは改ざん不可（append-only）か
- 認証失敗・権限エラーの多発を検知できるか
